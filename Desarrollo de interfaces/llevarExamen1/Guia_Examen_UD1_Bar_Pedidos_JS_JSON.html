Apartado b) Fuente local 'Permanent Marker' (0,5 puntos)
En estilos.css el @font-face solo define la fuente. Falta aplicarla con font-family (por eso este apartado se
olvida):
    body, input, select, button, textarea, table {
        font-family: 'Permanent Marker', cursive;           /* cursive = fuente de reserva */
    }

•       Se aplica al body para que cubra formulario y listados; los controles ya heredan por el reboot de Bootstrap,
        pero indicarlos evita sorpresas.
•       El nombre debe coincidir exactamente con el del @font-face: 'Permanent Marker' (con espacio y
        comillas).
•       Comprobación: F12 > pestaña Network (se descarga el .woff2) y Elements > Computed (font-family).

    TRAMPA Definir no es usar
    Sin la regla font-family la fuente se declara pero nunca se pinta. Tampoco toques el @font-face (la ruta
    ../fonts/... ya es correcta respecto a css/).



Apartado c) Clases en objetos.js (2 puntos)
Pedido (idpedido, cliente, idplato, unidades) y Plato (idplato, nombre, descripcion, precio): campos privados #,
constructor en el orden de las columnas y get/set por campo. Mismo patrón que Libro/Genero del otro examen,
pero sin toJSON porque el enunciado no lo pide.
Bar tiene tres métodos y cada uno devuelve algo distinto. Esto es lo que más se pierde si no se lee el enunciado:
    class Bar {
      async altaPedido(oPedido) {                       // -> respuesta {error, mensaje, datos}
        let datos = new FormData();
        datos.append("cliente", oPedido.cliente);       // campo a campo con los getters
        datos.append("idplato", oPedido.idplato);       // (idpedido NO se envia: autonumerico)
        datos.append("unidades", oPedido.unidades);
        return await peticionPOST("alta_pedido.php", datos);
      }

        async getPlatos() {                               // -> array de filas
          let respuesta = await peticionGET("get_platos.php", new FormData());
          if (respuesta.error) throw new Error(respuesta.mensaje);
          return respuesta.datos;                         // [{idplato, nombre, descripcion, precio}, ...]
        }

        async listadoPedidosCliente(nombreCliente) {     // -> string con la tabla HTML
          let datos = new FormData();
          datos.append("nombreCliente", nombreCliente);
          let respuesta = await peticionGET("get_pedidos_cliente.php", datos);
          if (respuesta.error) throw new Error(respuesta.mensaje);
          ...                                             // construir el HTML (apartado d.iii)
          return html;
        }
    }

•       Por qué no JSON.stringify(oPedido): con campos privados y sin toJSON() el resultado es {}. Enviar campo
        a campo con los getters evita el problema y no exige código extra.
•       Por qué throw en los errores: así getPlatos() puede cumplir su contrato (devolver un array) y quien la
        llama decide cómo avisar con un try/catch. Versión mínima aceptable: return (await
        peticionGET(...)).datos;.
•       Todo es async porque fetch es asíncrono: quien llame necesitará await.

    TRAMPA ok frente a error
    ajax.js de este examen devuelve {error: true, ...} cuando falla el HTTP. Todo el control de errores debe usar
    respuesta.error. Si copias if (respuesta.ok) del otro examen, siempre entrarás por la rama de «fallo» (undefined
    es falso).

Apartado d.i) Visibilidad y desplegable de platos (1,5 puntos)
Hay tres elementos que mostrar/ocultar: frmAltaPedido, frmListadoPedidosCliente y #listado. Patrón:
ocultar los tres y luego mostrar los que toquen.
    const frmAlta = document.getElementById("frmAltaPedido");
    const frmListado = document.getElementById("frmListadoPedidosCliente");
    const divListado = document.getElementById("listado");

    function ocultarTodo() {
      frmAlta.style.display = "none";
      frmListado.style.display = "none";
      divListado.style.display = "none";
    }

    async function mostrarFormulario(oEvento) {
      oEvento.preventDefault();
      ocultarTodo();
      switch (oEvento.target.id) {
        case "mnuAltaPedido":
          await cargarPlatos(); frmAlta.style.display = "block"; break;
        case "mnuListadoPedidosCliente":
          divListado.innerHTML = ""; frmListado.style.display = "block";              break;
      }
    }

    async function cargarPlatos() {
      try {
        let options = "";
        for (let p of await oBar.getPlatos())
          options += `<option value="${p.idplato}">${p.nombre}</option>`;   // value=id, texto=nombre
        frmAlta.lstPlatos.innerHTML = options;
      } catch (error) { alert("No se han podido cargar los platos: " + error.message); }
    }


    TRAMPA display = "" no muestra nada
    La hoja de estilos oculta form, #listado con display:none. Poner style.display = "" solo quita el estilo en
    línea y vuelve a mandar la hoja: sigue oculto. Para mostrar hay que escribir style.display = "block". (Tampoco sirve
    d-none: esta plantilla no la usa.)


    TRAMPA «Descripción visible» no es la columna descripcion
    El enunciado pide que el value sea idplato y la «descripción visible» sea el nombre del plato. Es el texto que se ve en la
    opción, no la columna descripcion de la tabla.



Apartado d.ii) Alta de un pedido (2 puntos)
    async function procesarAltaPedido() {
      let cliente = frmAlta.txtNombreCliente.value.trim();
      let idplato = frmAlta.lstPlatos.value;            // value del <option> = idplato
      let unidades = frmAlta.rdoUnidades.value;         // value del radio MARCADO (RadioNodeList)

        let oPedido = new Pedido(null, cliente, idplato, unidades);            // idpedido null: lo genera la BD

        alert(respuesta.mensaje);                               // exito o error: siempre alert

    }

  OJO El ejemplo del enunciado tiene un total mal calculado
  En la imagen (y en ejemplo_listado.html) aparece «SERRANITO, 4 unidades, 5.50, 22.50», pero 4 × 5,50 = 22,00. Es un
  error del ejemplo: calcula siempre unidades × precio. Tampoco hay ningún «Antonio» en los datos; los clientes reales son
  Paco, Juan, Susana y Gloria.


  TRAMPA Un nombre con espacios o mayúsculas distintas
  En la BD hay un pedido de «Paco » (con espacio final, idpedido 8). Con trim() en el cliente y la colación
  utf8mb4_spanish_ci de MySQL (ignora mayúsculas y espacios finales) «paco» y «Paco» encuentran los mismos
  pedidos. Si el cliente no existe, muestra un mensaje en vez de una tabla vacía.


  TRAMPA Concatenar en vez de sumar
  fila.precio + fila.unidades con strings concatena («5.504»). Convierte con Number() o parseFloat() antes
  de operar; fila.unidades * fila.precio funciona por coerción, pero no te fíes de ello.



4. Puntos fundamentales y trampas (JS y JSON)
4.1 Formato de los datos
Toda respuesta del servidor tiene la forma {error, mensaje, datos} y ajax.js ya la convierte en objeto
(.json()): no hagas JSON.parse de nuevo. Ejemplos:
 getPlatos           -> {"error":false,"mensaje":"...","datos":[{"idplato":"34","nombre":"SERRANITO",
                         "descripcion":"Bocadillo de origen sevillano.","precio":"5.50"}, ...]}
 listado cliente     -> {"error":false,"mensaje":"...","datos":[{"idpedido":"3","cliente":"Susana",
                         "idplato":"34","nombre":"SERRANITO","unidades":"3","precio":"5.50"}, ...]}
 error               -> {"error":true,"mensaje":"No se ha podido registrar el pedido: ...","datos":null}

Según la versión de PHP/MySQL los números pueden llegar como string ("5.50") o como número: por eso se
convierte con Number() antes de operar.
